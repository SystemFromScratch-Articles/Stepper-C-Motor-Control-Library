    The problem

    A stepper that loses steps is found on the bench, not in the code

    Microstepping drivers hide the physics: a current loop that lags at speed, a bus voltage that runs out, a rotor resonance, a dead time that distorts the current. Finding them on hardware costs boards and time; a library tested only on its own unit tests does not see them at all.

    The motor is a dynamic system

    A two-phase motor model with back-EMF, detent torque and friction shows load angle, loss of synchronism and resonance before the motor is connected.

    Quick start

    A driver instance, two loops, four callbacks¶

    Stepper-C needs two functions from your board — one that writes the PWM compare values and one that switches the gate drivers on or off — and two periodic calls: the fast loop in the PWM/ADC interrupt and the slow loop at 1 kHz.

    #include "sstep.h"

/* Board functions (your HAL) */
extern void board_pwm_set(const uint16_t compare[SSTEP_LEGS_MAX]);
extern void board_gate_enable(bool on);

static int pwm_write(void* ctx, const uint16_t cmp[SSTEP_LEGS_MAX])
{
    (void)ctx;
    board_pwm_set(cmp);
    return 0;
}

static int output_enable(void* ctx, bool on)
{
    (void)ctx;
    board_gate_enable(on);
    return 0;
}

static struct sstep motor;

void app_start(const struct sstep_config* cfg)   /* cfg.hal uses the two functions */
{
    (void)sstep_init(&motor, cfg);
    (void)sstep_enable(&motor);
    (void)sstep_move_to(&motor, 3200);           /* one revolution at 1/16 */
}

void adc_isr(uint16_t ia, uint16_t ib, uint16_t vbus)   /* 20 kHz */
{
    const struct sstep_sample s = { ia, ib, vbus };
    (void)sstep_fast_loop(&motor, &s);
}

void tick_1khz(void)
{
    (void)sstep_slow_loop(&motor);
}

    A complete configuration for the 17HS19-2004S1 motor on the B-G431B-ESC1 board is in Using the library. Before the first motor turns on the bench, run the same code in the software-in-the-loop diagram.
